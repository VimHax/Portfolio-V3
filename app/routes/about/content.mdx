A developer's job is to bring someone's vision to life but for me simply doing just that, the bare minimum, is not satisfying. During development I attempt to do the following things;

- Present all the choices when making a non-trivial decision, revealing their tradeoffs in depth,
- Explain technical details in an easy to understand manner to ensure mutual understanding of what's being built,
- Suggest changes or new features,
- Challenge ideas that go against the vision and / or user experience,
- Give attention to all the easy to miss smaller details,
- Be not afraid to learn new technologies,
- Understand the what, how and why of all the decisions being made and the code being written,
- Take responsibility for and take steps to prevent mistakes, etc.

Only when I follow through the things mentioned above, among others, do I feel satisfied, knowing that I have delivered the best I could have.

## Origin

<Image src={ProcessingImg}>
  A screenshot of one of my first Processing programs. It is a bouncing
  rectangle being traced with a color that is changing over time.

It all started in 2018 when I came across [Processing](https://processing.org). Whilst I have attempted programming a few times earlier it never really "clicked" for me, but this time was different. The visual nature of Processing and the low barrier to entry (thanks to the amazing tutorials by [Daniel Shiffman](https://thecodingtrain.com)) was an addicting combo. [P5JS](https://p5js.org) then was a natural stepping stone from Processing to the whole frontend world.

<Video src="/video/processing.mp4">
  The largest project I worked on in Processing. Something to note is that
  everything is drawn with primitives such as rectangles, circles and text.
</Video>

A few months later I came across tutorials for building Discord bots using the [Discord.js](https://discord.js.org) library. With my previous (little) experience with JavaScript this was, once again, a natural stepping stone to Node.js and the backend world.

I ended up learning a lot since then. I have made;

- Interpreted (in TypeScript) and compiled (in Rust with [LLVM](https://llvm.org)) programming languages,
- Basic Minecraft clones (in C with [OpenGL](https://www.opengl.org) and in Rust with [Vulkan](https://vulkan.org)),
- A basic GPU accelerated program which renders the mandelbrot set (in C with [CUDA](https://developer.nvidia.com/cuda)),
- A fun program which listens to you (with a keybind), runs it through [Whisper](https://openai.com/index/whisper) and finally runs the transcription back through a TTS to be able to "change the accent / voice" in "realtime",
- A desktop application (with [Flutter](https://flutter.dev)) that can play sounds through a Discord bot when a keybind is triggered,
- Impossible looking visual effects in [Minecraft](https://www.minecraft.net) using [core shaders](https://minecraft.wiki/w/Shader) (in [GLSL](https://en.wikipedia.org/wiki/OpenGL_Shading_Language)) and plugins (in Java with [Spigot](https://www.spigotmc.org)),
- Many websites with varying levels of complexity,
- Few Discord bots (with [Discord.js](https://discord.js.org)),
- A desktop application (with [Electron](https://www.electronjs.org)) for messaging (had text formatting, image attachments, automatic updates),
- A basic [neural network](<https://en.wikipedia.org/wiki/Neural_network_(machine_learning)>) that can classify handwritten digits without any libraries (in Rust with the [MNIST database](https://en.wikipedia.org/wiki/MNIST_database))
- Many small [P5JS](https://p5js.org) programs, generating some interesting looking procedural art, etc.

What's exciting is that there's still so so much left to learn. Just need the time, patience and curiosity!
